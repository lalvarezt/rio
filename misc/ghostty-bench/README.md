# ghostty-bench

An additional headless Rio benchmark suite adapted from [Ghostty's benchmark workloads](https://github.com/ghostty-org/ghostty/tree/48dde97e0413a27064e4c6182db3df6ee999db7d/src/benchmark). Existing Rio benchmarks are unchanged.

## Run

```sh
cargo build --release -p ghostty-bench
python3 misc/ghostty-bench/suite.py generate --output /tmp/ghostty-corpora --seed 42
python3 misc/ghostty-bench/suite.py run --data-dir /tmp/ghostty-corpora --output /tmp/rio-before.json
```

Save the binary before rebuilding another revision. Reuse the corpus directory. Run measurements sequentially on an idle machine, with the same power policy, dimensions, history limit, and flags.

```sh
python3 misc/ghostty-bench/suite.py run --binary /path/to/other/ghostty-bench --data-dir /tmp/ghostty-corpora --output /tmp/rio-after.json
python3 misc/ghostty-bench/suite.py compare /tmp/rio-before.json /tmp/rio-after.json --output /tmp/rio-comparison.json
```

`run --filter terminal-resize` selects a family. `--loops` multiplies each workload's operation count. Increase it if samples are too short. The executable also accepts individual files generated by Ghostty or captured from applications:

```sh
target/release/ghostty-bench terminal-stream --data /tmp/capture.vt --samples 7 --warmups 3
target/release/ghostty-bench terminal-stream --data /tmp/capture.vt --chunk-size 1 --io memory
```

The second command probes fragmentation cost. It is a different workload from 64 KiB reads.

## Coverage and differences

Source revision: Ghostty `48dde97e0413a27064e4c6182db3df6ee999db7d`. Workload shapes come from `src/benchmark/*.zig` and `src/synthetic/`. Attribution is in [LICENSE.ghostty](LICENSE.ghostty). The Rust and Python ports do not require Zig or the Ghostty checkout.

| Ghostty family | Rio operation and limits |
| --- | --- |
| `terminal-parser` | Integrated VT parser with an observation sink; no grid mutation. Callback accounting is included. |
| `terminal-stream` | `Processor::advance` into `Crosswords`, with configurable dimensions and history. No PTY, rendering, clipboard, or image decoding. |
| `codepoint-width` | Incremental Rust UTF-8 decoding and Rio width tables; `table` and decode-only `noop`. Ghostty's SIMD and libc alternatives are not ported. |
| `grapheme-break` | Incremental UTF-8 decoding and Rio's stateful UAX #29 tables; `table` and `noop`. |
| `osc-parser` | Ghostty's little-endian 64-bit length-prefixed payload files, capped at 4096 bytes per record. Rio frames payloads through its integrated parser. OSC semantic handlers are excluded. |
| `apc-parser` | VT framing and retained APC payload accumulation. Ghostty also parses Kitty commands; this port excludes that stage and base64/image decoding. |
| `terminal-resize` | `cols`, `rows`, `both`, and same-size `noop`, with deterministic mixed-width/styled scrollback populated before timing. Each operation returns to the initial size. Rio history is limited in lines, Ghostty's in bytes. |
| `screen-clone` | Fresh visible-row copies, full/clean snapshots, one-row damage, one-row or half-page history scrolling, and append-one-line updates. Scrolling reverses every 2000 or 40 operations, following Ghostty. `clone` copies visible cell rows, not all Ghostty screen-owned metadata. No shaping or GPU submission. |
| `terminal-formatter` | Visible-screen `plain` or `vt`, `format`, `roundtrip`, or `noop`. Roundtrip times replay into a fresh terminal; it does not establish lossless serialization. No HTML, history regions, pin maps, or reports. |
| `hyperlink-map` | Cell-to-extras lookup or clear/reassign of a shared interned hyperlink, at 25% and 100% occupancy. Rio uses extras IDs rather than Ghostty's page-local cell map. |

Unavailable operations fail explicitly. Page/scrollback compression, binary `terminal-snapshot` encode/decode, and `is-symbol` classification have no matching Rio primitive. The C API, renderer-lock-only, Kitty-placement snapshot, and alternate-screen/no-reflow special modes are not migrated. Adding surrogate implementations would measure new benchmark code instead of Rio.

The generator covers all five Ghostty input families: ASCII, UTF-8, styled text, OSC, and Kitty APC. Profiles include malformed UTF-8, combining marks, wide characters, hyperlinks, and invalid OSC payloads. Python uses a fixed seed per profile, not Zig's PRNG. These corpora are not byte-identical to Ghostty's generators. SHA-256 manifests pin the exact bytes used for each capture. Files end on record boundaries and can slightly exceed `--bytes`. Keep generated files outside the repository.

## Measurement boundaries

Each sample constructs a fresh workload before timing. Resize population, retained render snapshots, OSC record decoding, corpus verification, and output checksums are untimed. Retained measured snapshots are checked against a separate fresh reference without repairing their output. Stream/parser and Unicode workloads include file reads and rewind by default; `--io memory` excludes file I/O. OSC payload records are always preloaded. Unicode probes include incremental decoding; malformed input uses Rust's maximal-subpart replacement policy, not Ghostty's terminal decoder semantics.

`--loops` repeats operations on the same state within a sample. Warmups use separate state. A stream/parser operation replays the complete file. A resize operation is one shrink/grow cycle. Snapshot, formatter, and hyperlink operations each execute one viewport pass. Timings include mutation and reclamation performed by those operations. Process startup, setup, final destruction, and checksums are outside the internal timer. A `hyperfine` measurement of the executable includes them, so keep those results separate.

JSON captures contain individual sample times, medians per operation, options, output fingerprints, corpus hashes, binary hash, build optimization status, host platform, and compiler version. Build-time Rio revision/dirty state travels with saved executables; the runner records its own checkout separately as `harness_revision`/`harness_dirty`. Source archives report unknown provenance. Fingerprints detect drift between repeated runs, not terminal conformance. `compare` rejects invalid timings and different corpora, workload settings, build modes, or fingerprints. Ratios below 1 mean lower time for that Rio workload. They do not establish that Rio is faster than Ghostty.

Validate the port with:

```sh
cargo test -p ghostty-bench
python3 -m unittest discover -s misc/ghostty-bench -p test_suite.py
```

## Check chunk equivalence

```sh
python3 misc/ghostty-bench/suite.py check-chunks --hex eda080 --output /tmp/rio-chunks.json
```

This diagnostic compares parser and terminal fingerprints for identical bytes at chunk sizes 1, 17, and 65536. It writes a report and exits nonzero on disagreement. Use `--data PATH` for a larger captured corpus. Timing values in this diagnostic are not performance measurements.

The malformed UTF-8 sequence `ED A0 80` exposed different terminal snapshot fingerprints between one-byte and bulk reads. Commit `6e90c19603` fixes the native validator's error lengths, and this diagnostic now passes on HEAD. It remains useful when comparing older revisions.

## Compare upstream and HEAD

Build the same crate in each checkout. For upstream `59203ccd5f`, add the crate's workspace member entry and copy this directory without changing terminal code. The build script detects upstream's older snapshot container API. Both variants call the native `snapshot_visible` operation; normalization and validation happen outside timing.

```sh
python3 misc/ghostty-bench/suite.py paired --before-binary /tmp/ghostty-bench-upstream --after-binary /tmp/ghostty-bench-head --data-dir /tmp/ghostty-corpora --output-dir /tmp/rio-paired
```

The runner calibrates a common operation count per case toward 25 ms samples, warms both executables, then takes seven paired samples in alternating AB/BA order. All timings are sequential. `before.json` and `after.json` retain raw samples and binary provenance. `comparison.json` gives ratios only for matching output fingerprints. Output differences and failed cases are recorded separately instead of treated as speedups. Noops are overhead controls, not representative application workloads.
